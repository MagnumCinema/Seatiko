# Twenty CRM: логика подключения ресторанов

## Назначение

Twenty CRM — внутренний инструмент команды FoodAssistant. Владелец ресторана работает только в кабинете FoodAssistant: заполняет профиль, отправляет его на проверку, исправляет замечания, видит бронирования и историю действий. Доступ к внутренним заметкам, задачам и воронке CRM владельцу не выдаётся.

## Модель данных

| Twenty | Что хранит | Ключ синхронизации |
|---|---|---|
| **Person** | владелец или контактное лицо: имя, email, телефон, язык | `foodassistant_owner_id` |
| **Company** | ресторанная группа или юридическое лицо | `foodassistant_company_id` |
| **Restaurant Location** (custom object) | отдельное заведение: название, адрес, координаты, статус профиля, ссылка на кабинет | `foodassistant_application_id` / `foodassistant_venue_id` |
| **Opportunity** | процесс подключения конкретного заведения | `foodassistant_application_id` |
| **Task / Note** | звонок, проверка анкеты, запрос документов, внутренняя заметка | связь с Opportunity и Restaurant Location |

Один владелец может иметь несколько компаний, одна компания — несколько заведений. Поэтому ресторан нельзя хранить только как `Company`.

## Воронка подключения

1. **Новая заявка** — контакт создан, но анкета ещё не заполнена.
2. **Владелец зарегистрирован** — подтверждён аккаунт владельца.
3. **Настройка профиля** — добавляются адрес, график, меню, столы и фотографии.
4. **На проверке** — анкета отправлена модератору; автоматически создаётся задача проверки.
5. **Нужны исправления** — владелец получил конкретный список замечаний.
6. **Одобрено** — данные проверены, ресторан готов к публикации.
7. **Опубликовано / Won** — заведение появилось на карте и началось сопровождение.

Отказ или пауза закрывают Opportunity как `Lost` с обязательной причиной. Публикация и модерация остаются в FoodAssistant источником истины: изменение этапа вручную в CRM не должно само публиковать ресторан.

## События синхронизации

| Событие FoodAssistant | Действие в Twenty |
|---|---|
| Регистрация владельца | upsert Person, создать Opportunity «Новая заявка» |
| Создание анкеты | upsert Company и Restaurant Location, этап «Настройка профиля» |
| Обновление анкеты | обновить адрес, контакт, заполненность и время последнего изменения |
| Отправка на модерацию | этап «На проверке», задача модератору со сроком 1 рабочий день |
| Возврат на исправление | этап «Нужны исправления», Note с причиной, задача связаться с владельцем |
| Одобрение | этап «Одобрено», записать модератора и дату |
| Публикация | этап «Опубликовано / Won», записать Venue ID и ссылку на публичную карточку |
| Нет активности 3 дня | задача менеджеру помочь с заполнением |
| Нет активности 7 дней | задача позвонить владельцу, пометка риска |

Бронирования гостей в CRM поштучно не отправляются. Для сопровождения достаточно агрегатов: бронирований за 7/30 дней, отмен, no-show и среднего времени ответа. Телефоны и комментарии гостей остаются в операционной системе FoodAssistant.

## Надёжная архитектура

```text
Сайт / приложение владельца
          ↓
      FoodAssistant API ──→ база + audit log
          ↓                    ↓
      outbox events        кабинет владельца
          ↓
      CRM sync worker ──→ Twenty REST API
                              ↓
                    воронка, задачи, заметки
```

- Регистрация и сохранение анкеты не зависят от доступности Twenty.
- Событие сначала сохраняется в outbox, затем worker отправляет его с повторными попытками.
- Upsert выполняется по стабильным FoodAssistant ID, чтобы не создавать дубли.
- После ошибки сохраняются `sync_status`, `last_sync_at` и безопасное описание ошибки.
- API-ключ Twenty хранится только на backend; в браузер и mobile bundle он не попадает.
- Доступ ключа ограничивается объектами People, Companies, Opportunities, Tasks, Notes и Restaurant Location.
- Входящие webhooks Twenty принимаются только с проверкой подписи и используются для назначения менеджера или внутренних задач, но не для публикации ресторана.

## Что нужно для включения

1. В Twenty открыть **Settings → API & Webhooks** и создать отдельный API key для FoodAssistant.
2. Создать custom object **Restaurant Location** и поля синхронизации из таблицы выше.
3. Создать pipeline **Restaurant Onboarding** с семью этапами.
4. Передать backend-переменные `TWENTY_BASE_URL=http://twenty-server:3000` и `TWENTY_API_KEY`.
5. После получения ключа проверить фактическую REST-схему workspace и только затем включить worker.

Ключ нельзя добавлять в `NEXT_PUBLIC_*`: такие переменные попадают в клиентский JavaScript.
