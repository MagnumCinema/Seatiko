# Twenty CRM: интеграция с Seatiko

## Назначение

Twenty — внутренний рабочий кабинет команды Seatiko. Владелец ресторана регистрируется и управляет заведением только через Seatiko. CRM получает актуальную проекцию владельцев, ресторанов, гостей и бронирований, но не управляет авторизацией или публикацией.

## Фактическая модель данных

| Twenty | Что хранит | Ключ upsert |
|---|---|---|
| `People` | владельцы и гости: имя, email, телефон, роль и язык | `seatikoUserId` |
| `Companies` | одна заявка/ресторан: профиль, адрес, контакты, фото и lifecycle status | `seatikoId` |
| `Reservations` | дата, гости, стол, источник и рабочий статус брони | `seatikoReservationId` |
| `Tasks` | автоматические задачи подключения, связанные с рестораном | `seatikoTaskKey` |

Дополнительные идентификаторы `venueId`, `seatikoVenueId`, `seatikoTableId` и `seatikoUserId` позволяют проверить связи и восстановить синхронизацию без сопоставления по имени.

Docker-образ Seatiko создаёт новые рабочие пространства Twenty с пустыми стандартными таблицами. При сборке отключается загрузка примеров Twenty. Демо-профили Seatiko и их бронирования исключены из синхронизации с CRM.

## Подключение ресторанов и задачи команды

При первой успешной сверке API создаёт общее представление «Seatiko · Подключение ресторанов» в Companies. Канбан использует этапы заявки `DRAFT → SUBMITTED → UNDER_REVIEW → APPROVED → PUBLISHED`; отклонённые заявки находятся в отдельной колонке `REJECTED`. Публикация и модерация выполняются в админке Seatiko. Изменённый вручную этап в CRM возвращается к значению Seatiko при следующей сверке.

Автоматизация выполняется в API (NestJS, `backend/src/modules/crm`) вместе с reconcile и работает без отдельной настройки workflow Twenty.

| Условие | Задача и срок |
|---|---|
| Черновик без фотографий остаётся незаполненным 24 часа | Запросить фотографии у владельца |
| Заявка отправлена или находится на проверке | Проверить заявку; срок — 24 часа после отправки |
| Проверка длится более 48 часов | Дополнительная задача о просроченной проверке |
| Заявка одобрена | Опубликовать ресторан; срок — 24 часа после одобрения |
| Заявка отклонена | Обсудить исправления с владельцем; срок — 24 часа после отклонения |

Сроки задач помогают организовать работу команды; они не изменяют статус заявки автоматически. Задачи связываются с Company через стандартный `taskTarget`. Ответственный назначается в Twenty. Автоматизация сохраняет назначенного менеджера, заметки и ручное закрытие задачи. Когда условие исчезает, открытая задача закрывается автоматически. Если то же условие возникает снова, автоматически закрытая задача открывается повторно. Повторная отправка заявки запускает новый цикл проверки.

Настройка представления и панели выполняется через API Twenty и сохраняется в CRM. Повторная сверка и перезапуск Seatiko не создают копии. Добавляются только рабочие настройки и задачи по существующим заявкам.

## Панель Seatiko

В Dashboards автоматически создаётся панель «Seatiko — обзор» с вкладкой «Показатели». На ней пять нативных виджетов Twenty: количество заявок ресторанов, количество бронирований, заявки по статусам, бронирования по статусам и заявки по городам. Показатели охватывают всю историю и используют записи, связанные с Seatiko через внешние ID. Для времени задана зона `Europe/Chisinau`.

Графики читают актуальные записи CRM; новые данные появляются после синхронизации. Схема и конфигурация панели устанавливаются при запуске API, повторное создание завершённых элементов не требуется. Пользовательские виджеты и расположение уже созданных элементов сохраняются. Если переименовать один из начальных виджетов, при следующем запуске API начальный виджет будет добавлен снова под исходным названием.

## Двусторонняя синхронизация

### Seatiko → Twenty

1. Изменение сначала сохраняется в Seatiko persistent state.
2. API запускает reconcile после важной операции.
3. Фоновая сверка повторяется каждые 15 секунд.
4. REST upsert ищет запись по стабильному ID.
5. Relations связывают владельца с рестораном, а бронь — с гостем и Company.
6. Повторная доставка безопасна и не создаёт дубли.

### Twenty → Seatiko

1. Twenty отправляет `company.updated`, `person.updated` или `reservation.updated`.
2. API проверяет HMAC SHA-256, timestamp и допустимое окно времени.
3. Webhook, созданный нашим API-ключом, игнорируется как echo.
4. Ручное изменение разрешённого поля применяется к Seatiko.
5. В кабинете появляется `CRM_PROFILE_UPDATED`.
6. Reconcile возвращает нормализованное значение в CRM.

## Правила конфликтов

| Данные | Источник истины | Почему |
|---|---|---|
| Пароль, роль, user ID | Seatiko | CRM не должна управлять доступом |
| Owner application | Seatiko | нельзя незаметно передать ресторан другому владельцу |
| `DRAFT…PUBLISHED` | Seatiko | ручное поле CRM не должно публиковать ресторан |
| Профиль и контакты | последнее разрешённое ручное изменение | менеджер CRM и владелец могут исправлять данные |
| Статус брони | Seatiko или разрешённое ручное CRM-изменение | поддерживает звонок/приход/no-show |
| Timeline | обе системы | техническая и пользовательская история сохраняются отдельно |

Поля CRM проверяются теми же правилами, что форма: корректный email, HTTP/HTTPS сайт, допустимые координаты, price level 1–3 и неотрицательный средний чек.

## Границы интеграции

- В CRM попадают только пользователи и заведения, относящиеся к реальной заявке.
- Seed-точки карты без заявки владельца не создают Company.
- Бронь синхронизируется, если её venue связан с опубликованной заявкой.
- Заказы и высокочастотное состояние столиков остаются в операционном API; CRM получает бизнес-бронь, а не каждый UI-клик.

## Надёжность

```text
request → persistent state → HTTP response
              │
              ├── immediate reconcile trigger
              └── periodic reconcile / retry
                         │
                         ▼
                    Twenty REST

Twenty manual edit → signed webhook → validation → persistent state
```

- Сбой CRM не блокирует регистрацию, анкету или бронирование.
- Atomic JSON snapshot переживает рестарт контейнера.
- Uploads хранятся в отдельном volume.
- `/healthz` и `/api/v1/integrations/twenty/status` показывают состояние интеграции.
- Ошибка сохраняется в CRM status и очищается после успешной сверки.

## Локальная конфигурация

1. Запустите Docker Compose. Откройте Twenty и создайте workspace Seatiko. [Twenty CRM](http://crm.localhost/)
2. В настройках разработчика создайте ключ с доступом к модели данных, представлениям и макетам панелей, а также чтением и записью People, Companies, Reservations, Tasks, Task Targets и Dashboards. Запишите его как `TWENTY_API_KEY` в `.env.integration.local`. Создайте отдельный случайный `TWENTY_WEBHOOK_SECRET` в том же файле.
3. Выполните `docker compose up -d --build --force-recreate api`. API создаёт недостающие поля, объект Reservations, представление подключения и панель Seatiko, сохраняя существующие записи. При асинхронном применении изменений в Twenty следующая сверка продолжает настройку.
4. Создайте webhook в Twenty. Укажите URL `http://api.seatiko.local:8080/api/v1/integrations/twenty/webhook`, тот же секрет и события `person.updated`, `company.updated` и `reservation.updated`. При выборе роли укажите роль с доступом к этим объектам.
5. В админке Seatiko откройте вкладку CRM. На ней видны результат последней синхронизации и время последнего подписанного события.

Compose задаёт внутренний адрес CRM `http://twenty-server:3000`. Для локального webhook Compose отключает outbound safe mode Twenty. При развёртывании за пределами локальной сети включите safe mode и используйте публичный HTTPS URL webhook.

[Документация Twenty по webhook](https://docs.twenty.com/developers/extend/webhooks)

## Проверка

1. Изменить кухню тестового ресторана в Twenty.
2. Убедиться через Seatiko API, что новое значение применилось.
3. Вернуть исходное значение.
4. Проверить HTTP 200 webhook в логах API.
5. Запустить reconcile и убедиться, что число People, Companies и Reservations не изменилось.
6. Перезапустить API и проверить повторный вход и сохранность заявок.

Подробная инструкция и скриншоты: [`../seatiko/README.md`](../seatiko/README.md).
