## Задачи

### 1. Предзаказ блюд к брони — **Открыто**

**Контекст.** На странице меню гость собирает «Ваш выбор» (порции и сумма). Список хранится только в `localStorage` на устройстве и **не отправляется** в ресторан. Ссылка с подтверждения брони (`?preorder=1&table=…`) уже ведёт на меню, но это только подсказка гостю.

**Нужно на бэке (по `APP_LOGIC` §5.3 / §8.4):**

- [ ] Привязать позиции меню к брони (`reservation_id` + `menu_item_id` + `qty` + цена на момент заказа).
- [ ] API: создать / изменить / отменить предзаказ к своей брони; отдать предзаказ вместе с бронью (гость, владелец, staff).
- [ ] Учитывать стоп-лист, удаление блюда, смену цены; алкоголь и прочие `requires_age_18` — только при `adult_preorder_allowed` (задача 5).
- [ ] Опционально: флаг ресторана «готовить к приходу» / «после посадки» (уже есть идея в APP_LOGIC).
- [ ] Уведомление кухне / staff при новом или изменённом предзаказе.

**Сейчас на фронте:** `seatiko_menu_selection:<venueId>` в `localStorage`; на странице явно написано, что список в ресторан не уходит.

### 2. `GET /api/v1/availability` — **Открыто**

Пилот: `/book` считает свободные слоты в браузере (`venue-availability.ts`) по `GET /venues`, `/tables`, `/schedule` (1 + 2·N запросов).

Целевой контракт и требования — в [`ENGINEERING.md`](./ENGINEERING.md) § «Поиск свободных столов». После внедрения клиентская логика остаётся только для отображения.

### 3. Избранное ресторанов на сервере — **Открыто**

Сейчас избранное только в `localStorage` (`guest-local-prefs`). Нужны API + хранение на пользователе; заменить локальный список после логина.

### 4. Аллергии / диета в профиле — **Открыто**

Поля на `User` + `PATCH /me`; фронт кабинета уже рисует UI, данные не персистятся на сервере.

### 5. 18+ и предзаказ возрастных позиций — **Открыто**

По `APP_LOGIC` §8.4:

- [ ] Поля `adult_preorder_allowed` (+ метаданные кто/когда/где подтвердил) на пользователе.
- [ ] Staff API: grant / revoke после проверки документа; журнал.
- [ ] В меню предзаказа скрывать/блокировать `requires_age_18`, если флага нет.
- [ ] Повторная проверка при подаче алкоголя.

Без этого задача 1 не должна открывать алкоголь в предзаказ.

### 6. Реальные способы оплаты — **Открыто**

В кабинете гостя сейчас заглушки. Нужен платёжный провайдер (или явный «оплачу в ресторане» без карты) по правилам APP_LOGIC.

### 7. Координаты демо-ресторанов — **Открыто**

Метки на карте «Как добраться» иногда не совпадают с адресом (например Beermaster Pub). Поправить `lat`/`lng` в сиде (`memory.go` / демо-данные) и при необходимости backfill в persistence, как для меню.
