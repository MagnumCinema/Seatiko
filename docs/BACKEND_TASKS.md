### 8. `free_tables: 0` в ответе map places — **Сделано**

У `MapPlace.FreeTables` (и части числовых полей) стоит `json:",omitempty"`. При 0 свободных столов ключ пропадает из JSON, попап карты может не показать «0 столов», хотя бронь всё ещё доступна. Убрать `omitempty` у `FreeTables` (как у `Venue.FreeTables`) или явно отдавать `0`.

### 9. Локали EN/RO для Google-only мест — **Сделано**

`GET /map/places?lang=ru|en|ro` передаёт язык в Google Places (`SearchFood`), веб шлёт `lang=<locale>` и перезапрашивает карту при смене языка. Название и адрес Google-места приходят на языке запроса и копируются во все три локали ответа (`localizedSame`), поэтому гость видит текст на своём языке. Жёстко `ru` остался только в `Enrich` (поиск `place_id` для фото/отзывов, на вывод не влияет).

### 10. Discover AI (NL → prefs / ranked venues) — **Сделано**

`POST /api/v1/discover/ai` (`internal/discover`, `internal/handlers/discover_ai.go`): свободный текст RU/RO/EN → фильтры `/discover` → ранжирование ресторанов города. Читает Groq (`GROQ_API_KEY`, модель `GROQ_MODEL`, по умолчанию `openai/gpt-oss-120b`); без ключа или при любой ошибке модели — правила по ключевым словам, ответ всегда есть. Ответ: `prefs`, `query_string`, `ranked` (с причинами), `exact`, `source`, `explanation` + прежний `venues` для мобильного и старых клиентов. Веб: ассистент на `/discover` отвечает, даёт 3 места и «Показать на карте».

### 11. Live count «Найдено: N» для discover — **Сделано**

`GET /map/places` с параметрами `/discover` (`cuisine`, `type`, `budget`, `occasion`, `practical`, `lat`/`lng`) возвращает `filters: {total, matched, relax?}`; список мест не меняется. Фильтры — те же, что `filterAndRankPlaces` на вебе (`internal/discover/prefs.go`). Веб: «Найдено: N из M» на карте, при нуле — кнопка «Уберите „…“ — будет N».

### 17. GDPR / Удаление аккаунта гостя (`DELETE /api/v1/me`) — **Сделано**

Пароль обязателен, только гости. Обезличиваются профиль (имя, email, телефон, диета, избранное, аватар, 18+), пожелания к броням, контакты в листе ожидания и заявках на банкеты, удаляются уведомления; предстоящие брони и предзаказы отменяются; заказы остаются без персональных данных. Старые токены получают 401 `account_deleted`, вход невозможен, CRM-синк не восстанавливает данные, email освобождается. Веб: окно удаления в настройках `/account`.

### 18. Загрузка и хранение аватара гостя — **Сделано**

`POST/DELETE /api/v1/me/avatar`: JPEG/PNG/WebP по magic bytes (SVG и прочее — 415), до 5 МБ, защита от «бомб» по размеру холста, 10 загрузок в минуту на пользователя; сохраняется JPEG 512×512 (обрезка по центру, без EXIF). Хранилище — S3-совместимое (`internal/media`, подпись SigV4 без SDK; проверено на примере AWS и живом MinIO) или локальная папка. В docker-compose — MinIO Community (сборка Chainguard: официальные бесплатные образы MinIO не выпускаются с октября 2025), бакет создаётся `minio-init`, отдача через nginx `/media/`. Для AWS S3 / R2 — сменить `S3_*` у `api`.

### 28. Схема зала на сервере: бар, кухня, вход, поворот столов — **Открыто**

**Контекст.** Редактор во вкладке «Зал и QR» двигает и меняет размер бара и кухни, убирает и возвращает их, ставит вход на любую стену и поворачивает столы на 90°. `PUT .../venues/:venueId/tables` хранит только `number`, `seats`, `x`, `y`, `zone`, поэтому эти данные пока лежат в `localStorage` браузера, где их сохранил владелец (`seatiko:floor-layout:<venueId>`, `lib/floor-layout-store.ts`). На других устройствах — и у гостей на странице ресторана — видна расстановка по умолчанию: в зале бар у левой стены, кухня в правом верхнем углу, вход снизу справа; в остальных зонах только вход; столы без поворота.

**Нужно на бэке:**

- [ ] Поле `venues.floor_layout jsonb` (или своя таблица) в формате фронта: `{ "v": 1, "zones": { "<zone>": { "bar": {x,y,w,h} | null, "kitchen": {x,y,w,h} | null, "entrance": { "side": "top"|"right"|"bottom"|"left", "at": 0..1 } } }, "rot": { "<номер стола>": 90 } }`. Все числа — доли 0..1 зала 16:10, как `x`/`y` столов; зона без записи = расстановка по умолчанию, `null` = бара / кухни нет.
- [ ] Проверка: числа 0..1, `w`/`h` > 0, `side` из списка, в `rot` только `90`.
- [ ] `PUT .../venues/:venueId/tables` принимает необязательный `layout` и сохраняет его в той же транзакции, что и столы; `GET .../venues/:venueId/qr` (владелец) и публичный `GET /venues/:id/tables` (или `GET /venues/:id`) отдают `floor_layout`.
- [ ] Вместо `rot` в JSON можно завести колонку `tables.rotation` (0 / 90) — тогда поворот хранится у стола, а не по номеру.
- [ ] По желанию — серверная проверка, что столы не накладываются друг на друга и на бар / кухню / проход у входа (на фронте уже есть).

**На фронте после этого:** `lib/floor-layout-store.ts` читает и пишет через API (`parseLayout` / `serializeLayout` уже в этом формате); при первом открытии редактора перенести то, что лежит в `localStorage`, на сервер. Редактор держит центры столов внутри границ `clampX` / `clampY` бэка (x 0.08–0.92, y 0.12–0.88, `TABLE_CLAMP` в `lib/floor-layout.ts`) — если границы поменяются, обновить и там.
