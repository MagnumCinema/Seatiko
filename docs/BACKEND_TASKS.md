### 8. `free_tables: 0` в ответе map places — **Сделано**

У `MapPlace.FreeTables` (и части числовых полей) стоит `json:",omitempty"`. При 0 свободных столов ключ пропадает из JSON, попап карты может не показать «0 столов», хотя бронь всё ещё доступна. Убрать `omitempty` у `FreeTables` (как у `Venue.FreeTables`) или явно отдавать `0`.

### 9. Локали EN/RO для Google-only мест — **Сделано**

`GET /map/places?lang=ru|en|ro` передаёт язык в Google Places (`SearchFood`), веб шлёт `lang=<locale>` и перезапрашивает карту при смене языка. Название и адрес Google-места приходят на языке запроса и копируются во все три локали ответа (`localizedSame`), поэтому гость видит текст на своём языке. Жёстко `ru` остался только в `Enrich` (поиск `place_id` для фото/отзывов, на вывод не влияет).

### 10. Discover AI (NL → prefs / ranked venues) — **Сделано**

`POST /api/v1/discover/ai` (`internal/discover`, `internal/handlers/discover_ai.go`): свободный текст RU/RO/EN → фильтры `/discover` → ранжирование ресторанов города. Читает Groq (`GROQ_API_KEY`, модель `GROQ_MODEL`, по умолчанию `openai/gpt-oss-120b`); без ключа или при любой ошибке модели — правила по ключевым словам, ответ всегда есть. Ответ: `prefs`, `query_string`, `ranked` (с причинами), `exact`, `source`, `explanation` + прежний `venues` для мобильного и старых клиентов. Веб: ассистент на `/discover` отвечает, даёт 3 места и «Показать на карте».

### 11. Live count «Найдено: N» для discover — **Сделано**

`GET /map/places` с параметрами `/discover` (`cuisine`, `type`, `budget`, `occasion`, `practical`, `lat`/`lng`) возвращает `filters: {total, matched, relax?}`; список мест не меняется. Фильтры — те же, что `filterAndRankPlaces` на вебе (`internal/discover/prefs.go`). Веб: «Найдено: N из M» на карте, при нуле — кнопка «Уберите „…“ — будет N».
